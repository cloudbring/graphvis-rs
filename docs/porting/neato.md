# neato port (Graphviz 16.1.0)

`layout=neato` (and `-Kneato`) now runs a function-by-function port of
`lib/neatogen` plus the shared infrastructure the other non-dot engines need.
The old stand-in (`force_circular::layout_neato`) is no longer dispatched;
`force_circular.rs` still serves fdp, sfdp, twopi, circo, osage and patchwork
until their ports land.

Entry point: `gv_layout::neatogen::neatoinit::neato_layout(&mut Graph)`.

## Fidelity

`gv-diff` against C 16.1.0 goldens (built-in text metrics, see
`scripts/gen-golden.sh`):

| corpus | before | after |
|---|---|---|
| `tests/neato` (343 files; 307 at the start) | 62 exact, score 95.97/307 (31%) | 338 exact, score 338.6/343 (98.7%) |
| main corpus, the two `layout=neato` files | 0/12 nodes, 0/11 edges | both exact |
| main corpus overall (508 files) | — | no regressions; renderer/gv-diff fixes from this branch add exact files |

Node positions, edge splines, label positions, cluster and graph boxes match
C within the gv-diff tolerances on every `tests/neato` file except:

- `mode=hier` (2 files): DIGCOLA's `stress_majorization_with_hierarchy` is not
  ported; plain stress majorization runs instead.
- `overlap=ortho|orthoxy|...` (2 files) and `overlap=vpsc` (1 file): not
  ported (`cAdjust` needs `lib/common/ns.c` on a constraint graph; vpsc is the
  C++ `lib/vpsc`). No adjustment is applied.

Most layouts are bit-identical to C: floating-point expressions follow the C
source as compiled by clang with `-ffp-contract=on` (an expression `a*b + c`
is computed as `fma(a, b, c)`, a `float*float` product added to a `double` is
rounded to `float` first, `x - y*z` is `fma(-y, z, x)`), and every random
number, sort and container order reproduces macOS libc/cgraph behaviour.

### Validation

- `cargo run --release -p gv-diff -- --golden tests/golden/neato --baseline tests/golden/neato-baseline.json tests/neato`
  (ratchet test: `crates/gv-diff/tests/neato_fidelity.rs`).
- Corpus: `tests/neato/*.gv` is generated by `scripts/gen-neato-corpus.py`
  (fixtures and undirected wild graphs with `layout=neato` forced, plus
  hand-written cases for modes, models, start, pos/pin, len/weight, overlap
  modes, sep/esep, splines, pack/packmode, labels, ports, ratio/size, random
  graphs up to 120 nodes). Goldens: `scripts/gen-golden.sh` writes
  `tests/golden/neato/`. Cases whose C output is not reproducible run to run
  (`start=rand` uses the clock; `ngk10_4` reads uninitialised memory) and
  `model=circuit mode=KK` (segfaults in C 16.1.0) are excluded.
- A locally built, instrumentable C copy lives in `~/src/gv-ref/build-neato`
  (`run.sh`); it matches Homebrew's output to the last printed digit on almost
  all files.

## Deviations

- `mode=hier`, `mode=ipsep`, `overlap=ortho*|portho*|vpsc|ipsep` are not
  ported (see above). `overlap=ipsep` is a no-op in C's adjust step as well.
- `makeMultiSpline` (GTS router for multi-edges and boundary ports with
  `splines=true`) is not ported; such edges take C's fallback branch
  (`makeSpline` per edge, or straight lines when the path is direct).
- Prism's Delaunay triangulation is a Bowyer–Watson port, not GTS; the edge
  set matches for points in general position, but ties between co-circular
  points and the matrix entry order may differ (all prism corpus files are
  still exact).
- xlabel placement inserts equal Hilbert keys in reverse insertion order,
  approximating the cdt splay bag.
- `start=random` without a seed uses seed 1 (C uses the clock).
- `model=mds` with `mode=KK` indexes by layout id where C uses 1-based
  `AGSEQ` (undefined behaviour in C).
- Engines/attributes outside neato's code paths (`-n` / `Nop`, `dim>2` output
  via `z`, `splines=ortho` routing) are not covered; `splines=ortho` falls back
  to polylines.
- Renderer changes made for C parity (`gv-render`): edges without a spline get
  no `pos`; `arrowhead/arrowtail=none` produce no `e,`/`s,` point; degenerate
  graph boxes print as computed; clusters with no layout box get no `bb`.
  `gv-diff` now compares `bb` only for clusters.

## Handoff: shared API for fdp / sfdp / twopi / circo / osage / patchwork

Typical engine skeleton (mirrors `neato_layout`):

```rust
let src = graph.clone();
let mut g = LGraph::new(&src, 2, EdgeType::Line);   // graph_init + node/edge init
// ... compute g.nodes[n].pos (inches) for the nodes of a Sub ...
let (mut ccs, pinned) = pack::pccomps(&g);          // or pack::ccomps
neatogen::adjust::adjust_nodes(&mut g, &sub);       // overlap=... (twopi, circo)
neatogen::adjust::remove_overlap_as(&mut g, &sub, Some(flag)); // fdp
neatogen::neatosplines::spline_edges(&mut g, &mut sub, is_root); // translate + route edges
pack::pack_graphs(&mut g, &mut ccs, &pinfo);         // packGraphs with doSplines
common::utils::compute_bb(&mut g, &mut root, true);
common::postproc::gv_postprocess(&mut g, true);       // labels, xlabels, translation
g.write_back(graph);
```

Key types and conventions:

- `LGraph<'a>` borrows the parsed `Graph`; `nodes[i].pos` is `ND_pos` (inches,
  `ndim` components), `coord` is `ND_coord` (points, set by
  `neato_set_aspect`), `lw/rw/ht/width/height/shape` come from exact C node
  geometry. `edges[e]` carries `dist`, `factor`, ports, labels, `spl`.
- `Sub` is a node-induced subgraph (`nodes` sorted by sequence, `member`
  mask, `bb`, top-level `clusters`). `g.root_sub()` is the root.
- Iteration: `g.outs(sub, n)` = `agfstout..agnxtout` (ordered by head
  sequence, then edge), `g.ins`, `g.all_edges` = `agfstedge..agnxtedge`,
  `g.find_edge` = `agfindedge`.
- Randomness: `g.drand` (`drand48`, reseed with `srand48`), `g.crand`
  (`rand()`), `cutil::RkState`; sorting with `cutil::qsort_by`.
- Clusters: `g.clusters` (`LCluster { subgraph, bb, label, label_pos, border, children }`)
  and `g.root_clusters` are the C `GD_clust` arrays; `write_back` copies their
  boxes, and unregistered clusters keep an input `bb` attribute.
- Edge routing: `neatosplines::spline_edges0` handles `splines=` line,
  polyline, spline (pathplan), curved, self loops and multi-edges for any
  `Sub`; `common::splines::clip_and_install` is the generic installer (no
  `ND_rank`/virtual-edge logic yet: dot's port should add that).
- Overlap removal: `neatogen::adjust::{graph_adjust_mode, get_adjust_mode,
  remove_overlap_with}` with `AdjustData`; prism is in `neatogen::overlap`,
  Voronoi in `neatogen::voronoi`, scaling in `neatogen::scadjust`.
- sfdp can reuse `sparse::SparseMatrix` and
  `sfdpgen::post_process::StressMajorizationSmoother`.
