# graphvis-rs

**Pure Rust + WebAssembly, partial port of Graphviz 16.1.0** (`#forbid(unsafe_code)`, zero C/FFI dependencies), running natively on desktop/server and directly inside the browser via `wasm32-unknown-unknown`.

---

## Status

graphvis-rs is a work in progress. Output is not byte-compatible with Graphviz, and only part of Graphviz is ported.

- Every layout engine (`dot`, `neato`, `fdp`, `sfdp`, `twopi`, `circo`, `osage`, `patchwork`) is a function-by-function port of the Graphviz 16.1.0 C code; see `docs/porting/` for the module maps and the remaining differences.
- Output formats: `svg`, `json`, `json0`, `dot`, `xdot`, `canon`, `plain`.
- Text is measured with Graphviz's built-in font metric tables (the layout C produces when it is built without Pango), not with real font rendering.

## Measuring fidelity with `gv-diff`

`gv-diff` compares this port against C Graphviz 16.1.0. It reads `-Tdot` output that C produced for each file in `tests/wild` (the 488-file wild corpus) and `tests/fixtures` (20 upstream files), stored in `tests/golden/` (see `scripts/gen-golden.sh`), and scores node positions and sizes, edge splines, labels, cluster boxes, ranks and the graph bounding box within fixed tolerances of 1 to 2 points.

```sh
cargo run --release -p gv-diff -- --baseline tests/golden/baseline.json   # fails on regression
cargo run --release -p gv-diff -- --filter clust --worst 20               # inspect a subset
cargo run --release -p gv-diff -- --baseline tests/golden/baseline.json --update
```

`cargo test --workspace` runs the same check against the checked-in baseline.

Current results over 508 files (all engines are scored against C `dot` output, which is what the golden files contain):

| Metric | Result |
| :--- | :---: |
| Files matching C exactly | 109 / 508 (21.5%) |
| Mean score | 37.2% |
| Node sizes within 1 pt | 5,046 / 8,916 (56.6%) |
| Node positions within 1 pt | 707 / 8,916 (7.9%) |
| Edges within 2 pt | 388 / 11,679 (3.3%) |
| Cluster boxes | 29 / 355 (8.2%) |
| Ranks agree | 460 / 508 (90.6%) |
| In-rank order agrees | 360 / 508 (70.9%) |
| Graph bounding box within 1 pt | 154 / 508 (30.3%) |

## Performance

There is no maintained benchmark against C Graphviz. An earlier version of this README quoted a "96.7x faster" parse table; it compared C timed as one process launch per corpus (including `exec` and file I/O) with warm, in-process Rust, so it did not measure the same thing and has been removed. The `bench_phase1` and `bench_phase2` binaries in `crates/gv-cli` produced those numbers; do not rely on their C timings.

## Crate Architecture

- [`crates/gv-core`](crates/gv-core): Arena-backed `Graph` IR, geometry primitives (`Point`, `BoundingBox`, `Spline`), Graphviz 16.1.0 built-in font metrics LUT (`font.rs`), and the X11/SVG/Brewer color tables (`color_table.rs`, generated by `scripts/gen_color_table.py`) with `colorxlate` semantics (`color.rs`).
- [`crates/gv-parser`](crates/gv-parser): Re-entrant DOT lexer (`lexer.rs`), recursive-descent parser with cluster/subgraph lexical attribute inheritance (`parser.rs`), and canonical serializer (`canon.rs`).
- [`crates/gv-geom`](crates/gv-geom): Node shape sizing and perimeter ray clipping (`shapes.rs`, including recursive `record`/`Mrecord`, HTML `<TABLE>` labels, polygons, stars, cylinders, and compass ports) + Bezier spline routing and arrowheads (`splines.rs`).
- [`crates/gv-layout`](crates/gv-layout): Layout engines. `dot` is a partial port (`acyclic`, network simplex `rank`, `mincross`, `position`, `dotsplines`); `neato`, `fdp`, `sfdp`, `twopi`, `circo`, `osage` and `patchwork` are approximations (see Status).
- [`crates/gv-render`](crates/gv-render): Graphviz output renderers (`svg`, `json`, `json0`, `dot`, `xdot`, `canon`, `plain`).
- [`crates/gv-engine`](crates/gv-engine): High-level pipeline orchestrator (`render_dot`, `render_dot_all`).
- [`crates/gv-diff`](crates/gv-diff): Differential harness against C Graphviz goldens (see above).
- [`crates/gv-wasm`](crates/gv-wasm): `wasm-bindgen` browser & JS/TS bindings (`render`, `renderSvg`, `renderJson`, `inspectGraph`).
- [`crates/gv-cli`](crates/gv-cli): `dot-rs` CLI binary (`-T`, `-K`, `-o`, `-G`/`-N`/`-E`, several input files, every graph in a file) and timing binaries (`bench_phase1`, `bench_phase2`).

## Browser Usage (`@graphvis-rs/wasm`)

```js
import init, { renderSvg, inspectGraph } from '@graphvis-rs/wasm';

await init();
const svg = renderSvg('digraph G { a -> b [label="fast"]; }', 'dot');
document.getElementById('diagram').innerHTML = svg;
```
